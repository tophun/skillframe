# 신뢰도 스코어링 루브릭 (0-100)

전체 이슈를 **Haiku 에이전트 1회 호출에 배치로 넘겨** 채점한다(이슈마다 따로 부르지 않는다). 에이전트에게 아래 루브릭을 **그대로** 전달하고, 이슈당 `{id, score, reason}`만 반환받는다. CLAUDE.md 근거로 잡힌 이슈는 해당 CLAUDE.md가 그 문제를 실제로 명시하는지 이중 확인시킨다.

- **0** — 전혀 확신 없음. 가벼운 검토로도 무너지는 false positive이거나 기존(pre-existing) 이슈.
- **25** — 다소 확신. 실제일 수도, false positive일 수도. 검증하지 못함. 스타일 이슈면 관련 CLAUDE.md에 명시되지 않은 것.
- **50** — 보통 확신. 실제 이슈로 검증됐지만 nitpick이거나 실무에서 드묾. PR 전체 대비 중요도 낮음.
- **75** — 높은 확신. 이중 확인했고 실무에서 부딪힐 가능성 매우 높음. 현재 PR의 접근이 불충분. 매우 중요하거나 관련 CLAUDE.md에 직접 언급된 것.
- **100** — 확실. 이중 확인해 실제이며 실무에서 자주 발생함을 확인. 증거가 직접 뒷받침.

## 필터

**80점 미만은 제외.** 통과 이슈가 없으면 게시하지 않고 중단(또는 "이슈 없음" 코멘트).

75점에 걸린 실질 이슈(임계값에 아깝게 못 미침)는 게시에서 빼되, 사용자에게는 공유해 판단을 맡긴다.

## false positive 예시 (제외 대상)

- 기존(pre-existing) 이슈 — 이 PR이 만들지 않은 것
- 버그처럼 보이지만 실제로는 버그 아님
- 시니어 엔지니어가 지적하지 않을 현학적 nitpick
- 린터/타입체커/컴파일러가 잡을 것(import 누락, 타입 에러, 포맷팅) — CI가 별도로 돌린다고 가정
- 일반적 코드 품질(테스트 커버리지 부족, 문서 부족 등) — CLAUDE.md가 명시적으로 요구하지 않는 한
- CLAUDE.md 위반이지만 코드에서 명시적으로 침묵 처리된 것(lint ignore 주석 등)
- 의도된 것으로 보이거나 더 큰 변경과 직접 관련된 기능 변화
- 실제 이슈지만 사용자가 수정하지 않은 라인에 있는 것
