# PR Tone Rules

PR title과 body는 리뷰어가 빠르게 판단할 수 있도록 담백하고 구체적으로 쓴다.

## 기본 톤

- 한국어로 쓴다.
- 과장하지 않는다.
- 변명하거나 사과하지 않는다.
- 마케팅 문구처럼 쓰지 않는다.
- 구현자가 한 일보다 리뷰어가 확인할 변화에 초점을 둔다.

## 문장 방식

- 짧은 명사형 또는 평서형을 사용한다.
- "했습니다", "추가했습니다"를 반복하지 않는다.
- "작업", "수정", "개선"만으로 끝나는 흐린 표현을 피한다.
- 불확실한 내용은 추측처럼 쓰지 말고 확인한 범위만 적는다.

## 검증 표현

- 실행한 명령은 그대로 적고 결과를 간단히 붙인다.
- 실행하지 않은 검증은 `미실행`과 이유를 적는다.
- 실패한 검증을 숨기지 않는다.

## 예시

좋음:

```text
- PR 생성 스킬에 기존 PR 본문 보정 흐름 추가
- repository PR template을 유지하도록 승인 전 점검 강화
- 미실행: 통합 테스트 없음, 문서 변경만 포함
```

피함:

```text
- 이것저것 수정했습니다.
- 더 좋은 UX를 위해 개선했습니다.
- 아마 문제 없을 것 같습니다.
```
